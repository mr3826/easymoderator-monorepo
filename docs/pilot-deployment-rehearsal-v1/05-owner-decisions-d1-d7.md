## Supplemental AI image-data transfer condition

This is a privacy authorization condition, not an eighth D-decision. Source review found `AI_PHOTO_MATCH_ENABLED` defaults true and customer-photo extraction can pass an image through the shared Gemini-to-OpenAI fallback chain. No image was sent in this rehearsal. Keep photo matching false for a live pilot until the owner confirms the allowed image-data classes and both providers' applicable terms and account controls. If OpenAI image transfer is not authorized, the source must exclude OpenAI from image-bearing extraction and add a regression test before the feature is enabled.

This privacy flag does not disable all photo-triggered order selection. `order-flow.service.js` independently calls an image matcher for image-plus-purchase-intent messages; when `AI_VISION_ENABLED=false`, its text-only RAG tier still runs on the accompanying text and the caller accepts any returned products without checking confidence. The image bytes are not used by that RAG tier, but the candidate may still be selected for an order session. Do not treat the two false image flags as proof that photo-driven order selection is disabled. Before enabling that flow, require an explicit gate, synthetic Bangla/Banglish regression, and calibrated catalog-identity evidence.

## D-1 measurement conditions

Before any real-shop traffic, name an accountable operator and define the numerator, denominator, baseline, review window, and stop threshold for unsafe or incorrect replies, false holds, missed or late replies, inappropriate order prompts, wrong catalog matches, provider spend, and manual operator hours. Treat any merchant-reported reply-safety incident as an immediate stop. The inherited 1% Sentry condition only covers errors on `/api/mobile` or `/order` over 24 hours; it does not measure Messenger reply safety. These thresholds and owners remain unresolved, so D-1 is not approved by this recommendation.

Keep AI reply mode at `MANUAL`. Before exposing AI-generated drafts during a pilot, verify that a provider outage is visible to the merchant/operator and that fallback behavior does not create a misleading order prompt for a price question. Current source review found no Inbox listener for `llm_outage`, and no outage regression test covers Bangla/Banglish price questions. Separately, do not use photo-triggered order selection until text-RAG matching is gated and calibrated against exact catalog identity.
