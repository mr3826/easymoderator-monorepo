## Disposition

- Every risky mutation surface is **fail-closed at source in production mode**, strict-literal, independently verified by focused regression tests already attested in the frozen candidate (flag matrix 5 suites/32 tests; security suite 58/817). The dev-only unset fallback (`NODE_ENV!=='production'` in `ai-runtime-flags.js:26-31`) is deliberate lab ergonomics and cannot affect a production render — the renderer itself emits literal `false` and **fails the deploy render outright on any non-literal value** (`render-production-env.js:22-28,197-207`). It is recorded here so nobody mistakes it for a production default.
- **Structural safety properties (survey-verified with file:line):** DB-resident automation state (`shops.settings.ai`, `automation_mode`, per-channel `allow_order_creation`) can only *remove* capability beneath the env kill switches — it never grants a mutation env denies (`shop.service.js:605–628`, `ai-runtime-flags.js` precedence); per-request reads for AI/vision flags vs boot-time reads for config booleans means a flag flip needs a restart but a kill-switch denial is immediate; webhook-integrity middleware fails closed (missing signature 403 / missing secret 503, `webhook-signature.middleware.js:61–68`); payment status writes come only from verified webhooks (`payment-webhook.controller.js:210–219`) and screenshot-OCR payment trust was removed (`order-session-standalone.service.js:11–12`); human handoff defaults to MANUAL-mode human-first (30-min cooldown, in-app channel, `shop-defaults.js:61–65`), low-confidence hold threshold 0.75 fail-closed (`confidence-gate.service.js:27,56–58`); `META_HUMAN_AGENT_TAG_ENABLED` default false with outright block while permission ungranted (templateRequired.rule.js:33).
- **Historical-statement audit:** pre-change "photo matching shipped ON by default" descriptions remain in `docs/ai-cost/AI_ARCHITECTURE_VALIDATION.md:167–168,200` and `AI_COST_ASSUMPTIONS.md:10–11`; each file now opens with an explicit supersession banner (`AI_ARCHITECTURE_VALIDATION.md:4–5`, `AI_COST_ASSUMPTIONS.md:4`) added by `4c36dffc`, so the body reads as dated history rather than current claim — verified acceptable, no edit needed.
- **One effective-value exception to UNKNOWN, honestly labeled:** `MOBILE_API_ENABLED` is recorded **true in production** by the repo's own 2026-09-26 activation receipt (table above) — still owner-reconfirm via B-4. `PRODUCTION_DEPLOY_ENABLED` carries written false-after-deploy receipts in `PRODUCTION_TRUTH`/`EXECUTION_STATE` (latest-recorded state, console re-check at D-3 time).
- **No other production values were inferred.** Missing permission to read the droplet's effective environment is blocker B-4 (`00` ledger): the owner-side safe action is a redacted `docker compose --env-file .env.prod config` name/value dump of only the rows above, or `printenv` of exactly these variables, with secrets masked.
